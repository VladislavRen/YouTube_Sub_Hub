# Проверка перед передачей — 22 октября 2026

Основной сценарий проверен на реальных YouTube, LM Studio и Neo4j:
задание завершено как `completed` / `graph_synced`, продуктовая оценка —
`ready`, `production_ready=true`, **0,969**, без предупреждений.

## Проверенное окружение

- macOS Apple Silicon, Python 3.11.11; установка через `uv sync --locked --extra dev --python 3.11`.
- Neo4j 5.26.32 Community из закреплённого Compose image, авторизация включена,
  HTTP/Bolt доступны только на `127.0.0.1:7474/7687`.
- LM Studio: `google/gemma-4-e4b` для анализа и перевода.
- Перевод включён, `quality_mode=strict`, `graph_best_effort=false`.
- В первом основном прогоне медиа не скачивалось; для задания явно выбран `full_processing`,
  разрешающий публичный transcript provider. Глобальный профиль остаётся `data_api_only`.

Старый пароль не подходил к существующему тому Neo4j. Перед восстановлением доступа
сделана offline-резервная копия; пароль изменён через временный контейнер без сети
и опубликованных портов, после чего авторизация включена обратно. Новый пароль
сохранён только в локальном `.env`. Исходные 6011 узлов и 9804 связи не очищались.
Резервные копии и credentials исключены из комплекта для передачи.

Во время проверки исправлены потеря режимов при повторной постановке задания,
их передача в `worker-once`, ложный успех `doctor` при пустом JSON-ответе модели,
отсутствие временных меток в коротком prompt, обработка технических сокращений
и повторный перевод поля после неверной структуры ответа.
Оба пути записи Neo4j теперь учитывают ту же продуктовую оценку качества,
которую показывает API. Строгий режим не записывает результат с предупреждением
о качестве; при этом прежний граф остаётся до успешного обновления.

## Воспроизводимость и комплект

Чистый экспорт без локального `.env`, токена, библиотеки и моделей успешно
установлен в отдельном окружении из `uv.lock` (89 установленных пакетов).
Первый полный pytest после основных исправлений: **731 passed** за 44,11 с; одно upstream-предупреждение
Starlette о будущем переходе test client на httpx2. `uv lock --check`, `uv pip check`,
`compileall` и `git diff --check` успешны. Собраны wheel и sdist.
Архив после проверки дополнительных режимов распакован в новый каталог
и установлен с нуля: **754 passed** за 61,71 с; предупреждение Starlette остаётся прежним.

Перед публикацией на GitHub исправлен нестабильный тест параллельного discovery:
вместо требования запуска потоков с разницей менее 50 мс он проверяет фактическую
одновременную работу ровно двух запросов через событие синхронизации.
Исходники сервиса и lock-файл при этой корректировке не менялись.
Повторный полный прогон: **754 passed** за 43,45 с; архив обновлён вместе с тестом.

Для передачи используйте полный архив исходников из `dist`:
в отличие от wheel, он включает Compose, lock-файл, пример настроек, тесты
и [инструкцию развёртывания](self-hosting.md).

`MANIFEST.sha256` внутри архива содержит хеши файлов; рядом с архивом лежит
его SHA-256. Локальные credentials, исходная библиотека, Docker-том, резервные
копии, виртуальные окружения и пользовательская папка `outputs` в архив не входят.

## Границы проверки

- У текущего Google-аккаунта нет собственного видео с captions. Успешное скачивание
  через официальный `captions.download` проверить было не на чем; проверены
  работа OAuth/metadata и корректный отказ для чужого видео. Коллеге нужен свой
  Google-проект/клиент и собственный token; чужой token не передаётся.
- Дополнительные режимы затем проверены вживую на трёх фрагментах видео Карпати.
  Результаты и исправления приведены в [отдельном отчёте](optional-modes-validation-2026-10-22.md).
  Для research и vision в нём отдельно описаны границы смысловой точности.
- Проверена установка на этой macOS-машине. Linux/WSL2 описаны в инструкции,
  но отдельно на другой ОС в этом прогоне не разворачивались.
- Qwen с текущими reasoning-настройками не укладывался в 120 секунд. Для передачи
  выбран проверенный профиль Gemma; другую модель нужно проверить отдельно.

Версии, dependency audit и требования Google приведены в
[отчёте об исправлениях](deployment-fixes-2026-10-22.md).
