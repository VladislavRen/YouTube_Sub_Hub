# Исправления перед передачей сервиса — 22 октября 2026

Зависимости обновлены, Google OAuth восстановлен и подтверждён реальным запросом
из клиента сервиса. Для коллеги подготовлена [инструкция развёртывания](self-hosting.md)
со своим Google-проектом, Desktop client, токеном и пустой библиотекой.
Изменения находятся в рабочей ветке `codex/deployment-readiness`.

## Что исправлено

| Область | Результат |
| --- | --- |
| Зависимости | Пересобран `uv.lock`, обновлены совместимые версии прямых и транзитивных пакетов. Установка через `uv sync --locked --extra dev --python 3.11`. |
| OAuth | `yt-sub-hub-auth` читает `.env` и явные пути, использует Desktop loopback OAuth с PKCE/offline access, проверяет выданные scopes и атомарно сохраняет credentials с правами `0600` на POSIX. Ошибка согласия не портит старый файл. |
| Доступ к API | Клиент больше не подменяет сохранённые scopes требуемыми при чтении токена. Добавлена поддержка системного HTTP CONNECT/SOCKS-прокси и PySocks: на этой машине OAuth работал через системный прокси, а API ранее пытался подключаться напрямую и зависал на TLS. |
| Квоты discovery | Поиск и остальные методы имеют отдельные бюджеты. SQLite ledger сохраняет расход одного run между стадиями, процессами и повторными попытками; неудавшиеся запросы учитываются. Остаток суточной квоты Google-проекта не выдумывается. |
| Свежие данные | `process URL --refresh` заново получает метаданные и транскрипт, инвалидирует производные результаты и не возвращается к старым исходникам при ошибке. Обычный `--force` сохраняет возможность использовать свежий кэш. |
| Возраст кэша | Исходные метаданные и транскрипты старше 30 дней не используются в CLI/staged pipeline. Повторный анализ не продлевает возраст исходников. `cache-cleanup` показывает просроченные исходники, `--apply` удаляет только их. |
| Сохранность результатов | Заметки перед обновлением резервируются. Блокировки защищают refresh/cleanup от активных воркеров. Основные связи Neo4j заменяются одной транзакцией; research/discovery-связи сохраняются, ошибка записи откатывает замену. Visual frame cache также учитывает обновление источников. |
| Media fallback | `yt-dlp[default]` включает EJS; `doctor` проверяет EJS и наличие JS runtime при включённом media fallback. Для Node.js >=22 нужна настройка `YT_SUB_HUB_YTDLP_JS_RUNTIME=node`. |
| Локальное развёртывание | Neo4j 5.26.32 Community закреплён по digest, порты опубликованы на loopback, пустой пароль отклоняется Compose. |
| Benchmark | Пул процессов переиспользует воркеры вместо импорта SDK для каждого короткого chunk. Общий deadline продолжает принудительно останавливать зависшие запросы; HTTP-клиенты перевода закрываются и при ошибках. |
| Повторные задания | API и `enqueue-video` применяют явно переданные режимы к повторному заданию. Смена режима активного задания отклоняется до изменения legacy-состояния. `worker-once` использует режимы самого задания. |
| Проверка модели | `doctor` требует законченный JSON `{"ok": true}`; HTTP 200 с пустым или обрезанным ответом больше не считается успехом. В примере используется проверенная локально Gemma. |
| Русский анализ | В prompt явно указан язык транскрипта. Короткие названия сохраняют известные технические сокращения AI/API/MCP/LLM; обычный английский текст по-прежнему отклоняется. При ошибке структуры одиночное поле переводится повторно по простой текстовой схеме, без выдуманного русского заполнителя. |

## Что остаётся настроить оператору

Коллеге нужен собственный OAuth token: передавать чужой token/client JSON/cookies
вместе с сервисом нельзя. Google `youtube.force-ssl` по-прежнему подходит для
captions, но скачивание требует прав редактировать конкретное видео; доступ к
чужому публичному ролику этого права не даёт.
[Требования captions.download](https://developers.google.com/youtube/v3/docs/captions/download).
Для External + Testing refresh token обычно живёт 7 дней; текущий статус
Testing/Production в Cloud Console не изменялся и не подтверждён.
[Сроки токенов](https://developers.google.com/identity/protocols/oauth2#expiration).

Neo4j на этой машине запущен. Результаты live pipeline и границы проверки
приведены в [итоговом отчёте](handoff-validation-2026-10-22.md). Реальная загрузка
медиа не выполнялась. Порты, модели и credentials на машине коллеги проверяются отдельно.
Поддерживаемая инструкция рассчитана на macOS/Linux; для Windows нужен WSL2,
поскольку библиотечные блокировки используют POSIX `flock`.

30-дневная проверка относится к исходным файлам. Производные результаты,
discovery-данные, медиа, заметки/резервные копии и сохранённый граф не удаляются
командой `cache-cleanup`. Нужна отдельная политика обслуживания и удаления этих
категорий; реализованный refresh не является полной проверкой соответствия
[политикам YouTube](https://developers.google.com/youtube/terms/developer-policies#handling-youtube-data-and-content).
Раздельные локальные бюджеты discovery также не заменяют мониторинг фактических
[квот проекта](https://developers.google.com/youtube/v3/determine_quota_cost) в Cloud Console.
